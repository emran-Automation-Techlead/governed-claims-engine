# Pillow advisory review (Milestone 5 follow-up)

Reviewed 2026-10-27. Package: **Pillow 12.3.0** (transitive dependency of Gradio 6.30.0). Scope: the demo application and its container.
Not a penetration test. Data: OSV / GitHub Advisory Database records retrieved 2026-10-27 (`pillow_advisories.json`, regenerated by
`scripts/pillow_advisory_review.py`); the dependency audit is `pip-audit 2.9.0` on `requirements-container.txt`.

## 1. Bottom line

* **37 advisories** affect Pillow 12.3.0: **4 CRITICAL, 22 HIGH, 11 MODERATE** (section 2, each listed individually).
* **Every one of them is fixed only in Pillow 13.0.0.** There is no 12.x backport in any record.
* **Pillow 13.0.0 is not a patched release that Gradio declares compatible**: every Gradio release up to the latest (6.30.0, checked on PyPI 2026-10-27)
  requires `pillow<13`. A compatibility experiment is reported in section 4; **it does not change the decision**, because an unsupported
  combination is not something this project can vouch for.
* **No code path that decodes, encodes or processes an image is reachable through the application as built and as served** (section 3). That conclusion rests on
  specific, tested controls (section 5), not on the application binding to loopback. If those controls are removed, the risk is real and severe (several
  advisories are remote-triggerable by a crafted image and rated CRITICAL).
* **Status: ACCEPTED, TIME-BOXED RISK** (expires 2026-12-31, enforced in CI). It is **not** "resolved".

## 1a. Re-review on 2026-10-28 (supersedes the counts in section 1)

A CI run on 2026-10-27/28 failed the allowlist gate because the advisory database re-keyed and extended its Pillow records. Findings, each checked against OSV:

* **Re-keyed, not new:** `PYSEC-2026-4326` is `GHSA-27h8-gf7j-v5hc` (CVE-2026-112392) and `PYSEC-2026-4328` is `GHSA-4rr5-89j8-mwwm` (CVE-2026-112396). Both were already reviewed.
* **One genuinely new record:** `PYSEC-2026-4327` = CVE-2026-112394 / `GHSA-4558-3h8r-v8xp`, a raw `P;2L`/`P;4L` decoder read past the end of an input buffer (low severity, fixed in Pillow 13.0.0). It needs an untrusted image to reach `Image.open()`, which this application never does (section 3).
* **Reported by Trivy, not by pip-audit (three records):** CVE-2026-112403 / `GHSA-8g5g-8vmr-9782` (critical), CVE-2026-112902 (high, libtiff encoder memory disclosure) and CVE-2026-112898 (medium, empty-palette quantization information disclosure), all fixed in 13.0.0. The first is a heap buffer overflow in `ImagingJpegDecode` (CVSS 4.0 vector with high confidentiality, integrity and availability impact; fixed in 13.0.0). OSV lists it by git commit range, not by package version, so `pip-audit` does not match it. It is the same class as the other decoder records (needs an untrusted JPEG decoded by Pillow) and has the same disposition. It is documented here but cannot be allowlisted by id because the gate only sees `pip-audit` output.
* **Net:** 38 advisories are listed by `pip-audit` (table below), plus the three Trivy-only records: 41 distinct advisories, all fixed only in Pillow 13.0.0. The accepted-risk entry was re-dated 2026-10-28 and still expires 2026-12-31.
* **Compatibility experiment (throwaway environment, project untouched):** the full suite gave 590 passed / 3 skipped with Pillow 12.3.0 and the same with Pillow 13.0.0 forced over Gradio 6.30.0; `pip check` reports the expected conflict (`gradio 6.30.0 requires pillow<13`). This is evidence that the upgrade is probably low-friction once Gradio allows it, not a supported configuration. The decision in section 4 stands.

**Exploit prerequisites, in general.** Almost all records need an attacker-controlled *image file or image-derived data* to reach a Pillow call
(`Image.open()/load()` for decoders; `save()`/`transform()`/filters/font drawing for the others). Many are denial of service (infinite loops, quadratic time, memory
amplification, decompression-bomb bypass); the CRITICAL ones are memory-safety bugs (heap overflow in TIFF/FPX handling, multi-frame storage reuse) or argument
injection into an external Ghostscript process (EPS). Three need unusual conditions: EPS needs a Ghostscript binary on the host; the WMF/EMF record applies to Windows
builds; the Arrow-export record needs `PILLOW_ALIGNMENT > 1`.

## 3. Reachability analysis

**Method.** Static inspection of Gradio 6.30.0's source for every use of PIL, plus live probing of the served application, plus an automated test of the UI's component types.

1. **Project code never imports Pillow.** PDF text extraction uses PyMuPDF; the synthetic PDF generator (reportlab) is a dev-time script, not part of the container.
2. **Where Gradio itself calls Pillow** (`PIL.Image.open/save/resize/convert`, `ImageOps`, `ImageSequence`, `PngImagePlugin`): `image_utils.py`, `processing_utils.py`
   (`save_pil_to_cache`, `save_img_array_to_cache`), the image-type components (`Image`, `ImageEditor`, `ImageSlider`, `AnnotatedImage`, `Gallery`),
   `pipelines_utils.py` (model pipelines), `mcp.py` (MCP server), `workflow.py`, `templates.py`, and one HTTP route (`/pwa_icon/{size}`).
3. **UI components.** The UI contains only `Accordion, Button, CheckboxGroup, Column, Dropdown, Form, HTML, JSON, Markdown, Radio, Row, State, Tab, Tabs, Textbox`.
   None decodes images. A test (`test_ui_contains_no_component_that_decodes_images_or_accepts_files`) fails if an image, file, audio, video, gallery, chat,
   editor or dataframe-type component is ever added, forcing this analysis to be redone.
4. **`/pwa_icon/{size}`** opens the *server-configured* favicon path (`blocks.favicon_path`), not user input; with no favicon configured it returns 404. It is additionally blocked.
5. **Unauthenticated upload (found in this review).** Probing the live server showed `POST /gradio_api/upload` returns **200** and stores the file in Gradio's temp directory
   *even though no component uses it* (file serving of arbitrary paths returned 403; `/file=` 404). This was missed in the M4 review. It is not a Pillow call by itself (stored files
   are only decoded if a component consumes them, and none does), but it (a) lets any client fill the disk and (b) is exactly the delivery route an image-based exploit would need if a
   consuming component were ever added. **It is now blocked** (section 5).
6. **Not enabled:** MCP server (`mcp_server` off), Gradio workflow builder, example caching of images, `gr.Examples` with images, any model pipeline.
7. **Ghostscript** (needed for the EPS advisories) is not installed in the default `python:3.11-slim-bookworm` image to my knowledge - **unverified, because no image has been built**.

**What this analysis is not.** It is not a proof. It depends on (a) Gradio's code paths as of 6.30.0, (b) the component-type guard and route blocks staying in place, (c) no new
feature that touches images, and (d) the correctness of my reading of the source. A Gradio upgrade can change (a); this is why the acceptance is time-boxed and re-checked.

## 4. Is a patched, compatible version available?

* Pillow **13.0.0** is the only version that fixes the records. No 12.x fix exists.
* Gradio's declared constraint is `pillow>=8,<13` for 6.10.0 and for 6.30.0 (the latest on 2026-10-27). So the combination "patched Pillow + supported Gradio" does not exist today.
* **Compatibility experiment (isolated throw-away venv outside the project; project not modified):** gradio 6.30.0 + Pillow 13.0.0 (installed with --no-deps over the resolved set) -> pip check reports the expected conflict (gradio 6.30.0 has requirement pillow<13.0,>=8.0, but you have pillow 13.0.0); the project's demo tests (	est_demo_service.py + 	est_demo_app.py: live server, real client sessions, escaping, routes, headers) -> **104 passed**. Interpretation: Gradio imports and serves normally with Pillow 13.0.0 and nothing the demo exercises breaks. **Limits of that evidence:** the demo uses no image component, so the tests do not exercise any Pillow call at all; the combination is outside Gradio's declared range; no image-handling regression testing was done; the experiment venv was discarded. It tells us the upgrade path is *probably* low-friction once Gradio permits it, nothing more.
* **Decision:** do not force Pillow 13 into the project. A passing test run does not make the combination *supported*: Gradio's authors have declared it out of range, `pip check`
  would fail, and the test suite does not exercise image components at all (which is where Pillow behaviour changes would show up).

## 5. Compensating controls (implemented and tested)

| Control | Implementation | Test | What it does and does not do |
|---|---|---|---|
| No image/file/media components | UI built only from the 15 component types in section 3 | `test_ui_contains_no_component_that_decodes_images_or_accepts_files` (mutation-checked: adding `gr.Image` fails it) | Removes every Gradio code path that calls Pillow on user data. Does not protect against a future developer who changes the test. |
| Upload, file-serving and icon routes blocked | middleware `BLOCKED_PATH_PREFIXES` returns 404 for `/gradio_api/upload`, `/upload`, `/gradio_api/file*`, `/file=`, `/pwa_icon*`, `/gradio_api/resource*` (case-insensitive; bounded body drain) | `test_upload_and_file_serving_routes_are_blocked`, `test_blocked_uploads_leave_nothing_in_the_gradio_cache` (unique marker; checked that with the block disabled the file *does* land on disk), `test_blocked_routes_keep_security_headers_and_do_not_break_the_app` | Stops attacker bytes reaching disk or any decoder via HTTP and closes the disk-filling hole. Does not cover other undiscovered routes. |
| No project use of PIL | code review + grep | (none beyond review) | n/a |
| Non-root, read-only filesystem, no capabilities (container configuration) | `Dockerfile`, `compose.yaml` | static config tests only - **image not built or run** | Limits blast radius of a memory-safety bug *if* the image behaves as written. Unverified. |
| Loopback binding by default; explicit opt-in for other hosts | `check_host`, compose publishes to `127.0.0.1` | `test_non_loopback_binding_is_refused_without_explicit_opt_in` | Reduces who can reach the app; it is **not** a reason to dismiss the advisories. |
| Time-boxed, individually enumerated acceptance enforced in CI | `governance/accepted_advisories.json` + `scripts/check_audit_allowlist.py` | `tests/test_dependency_governance.py` (fails on any new advisory, another package, a different Pillow version, or after expiry) | Prevents the accepted risk from silently masking new findings or being forgotten. |

## 6. Residual risk (precise statement)

Pillow 12.3.0 with 37 known, mostly HIGH/CRITICAL, image-handling vulnerabilities is present in the application's runtime environment, as a transitive import of Gradio.
With the controls above intact, the application offers an external actor **no way to deliver an image or file to any Pillow code path**, so exploitation of these advisories
through the application is **not currently possible as far as this review could determine**. The residual risks are: (1) a control regresses or is bypassed (an unknown Gradio route,
a Gradio upgrade that changes behaviour, a deliberate feature change); (2) my reachability reading is wrong or incomplete; (3) a supply-chain or local-file route
that places a crafted image where Gradio loads it (none identified); (4) the unverified container (Ghostscript presence, user/filesystem settings). Probability is judged **low**,
impact if it occurred is **high** (up to code execution for the CRITICAL records under their prerequisites). No quantified claim is made.

## 7. Conditions under which the application MUST NOT be used or exposed

The application **must NOT be exposed** to untrusted networks (public internet, shared or multi-tenant networks, any network you do not control), and must not be used with real data, while
**any** of the following holds - loopback binding alone does not satisfy these:

1. Pillow is below a fixed version (13.0.0) **and** any of: an image, file, audio, video, gallery, chat, editor or dataframe component is added; the upload/file/icon route blocks are removed or
   bypassed; MCP, Gradio workflows or any model pipeline is enabled; any code opens, converts, resizes, thumbnails or saves images (including PDF-to-image rendering) with Pillow.
2. The container has not been built and verified (non-root, read-only, no capabilities, no Ghostscript) and is intended for use beyond local testing.
3. There is no authentication/authorisation in front of the service (see `GRADIO_SECURITY_REVIEW.md`).
4. `pip-audit` reports any advisory outside the reviewed allowlist, the Pillow version differs from 12.3.0, or the acceptance has expired without a fresh review.

## 8. Exit criteria and review

* **Close the risk** by upgrading Pillow to >= 13.0.0 once a Gradio release permits it (Dependabot watches pip, GitHub Actions and Docker), then re-run the full suite and a browser check,
  or by replacing the UI framework. Remove the acceptance entry.
* **Acceptance expires 2026-12-31.** CI fails after that date until a person re-reviews (`scripts/check_audit_allowlist.py`).
* Re-run this analysis after every Gradio upgrade, and whenever a component or route is added.
