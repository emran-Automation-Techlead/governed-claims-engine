## 3. Abstention calibration (requirement 8)
* Labelled calibration set: 64 cases (36 answerable, 28 unanswerable: off-topic, adjacent-topic, function-word-only, odd
  input), queries disjoint from M2 and held-out (tested).
* Rule fixed in advance: smallest grid value with zero false accepts, plus one grid step.
* `tau_lex = 0.5` (zero-FA value 0.45), `tau_sem = 0.66` (zero-FA value 0.64). Lexical gate on calibration data:
  answer rate 0.833, false accepts 0/28. Rule-of-three 95 % upper bound on false-accept rate: ~11 %.
* On the calibration set itself the numbers are optimistic by construction; see section 4 for data not used to fit.
* Sensitivity: `tau_sem` 0.60 and 0.62 each admitted one unanswerable query; the curve is steep.

* HO25 ("Wasserschaden", German home policy): the system cited clause 2.2 (water cover) and said *potentially
  covered*; my label expected review/insufficient because I treated the query as a definition lookup. On rereading the
  label is arguably too strict, but labels were frozen before running, so the number stands.
* Weakest categories: German compounds (acceptable 0.429 lexical / 0.714 semantic), cross-lingual in lexical mode
  (verdict coverage 0.0 by design), paraphrase (verdict coverage 0.0 lexical / 0.2 semantic). The system prefers
  abstaining there.
* The 52 M2 cases through the whole workflow: 18 answerable cases got a verdict citing only relevant clauses in both
  modes; semantic mode had 1 off-target citation (Q37, same label-strictness issue as HO25); the remaining answerable
  cases were abstained or escalated (31 lexical, 30 semantic). 0/3 unanswerable cases received a verdict.
* **Coverage is low.** Most questions that are not near-verbatim clause language end in abstention. That is the intended
  trade-off, but it means this baseline assessor is a cautious clause finder, not a useful claims assistant.
